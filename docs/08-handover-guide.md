# Website Handover Checklist

| Version | Date | Author | Notes |
|---------|------|--------|------|
| 1.0 | July 2026 | Cindy Cheng | Initial documentation |

## Purpose

This checklist should be completed whenever responsibility for the website passes to a new volunteer.

The goal is to ensure that knowledge is transferred before the previous maintainer leaves.

---

# Technical Handover Meeting

Arrange a meeting between the outgoing and incoming maintainer.

During the meeting:

- explain the project structure
- demonstrate deployment
- explain GitHub
- answer questions

Avoid relying solely on written documentation.

---

# Practical Demonstration

The incoming maintainer should complete each task independently.

□ Clone the repository

□ Install dependencies

□ Run:

```bash
npm install
npm run dev
```

□ Open the local website

□ Make a small text change

□ Build the website

```bash
npm run build
```

□ Commit the change

□ Deploy successfully

□ Log into Decap CMS

□ Publish a test edit

□ Watch Cloudflare deploy

□ Verify website updates

---

# Content Management

Incoming maintainer understands:

□ How Decap CMS works

□ How content is organised

□ How to restore deleted content

□ Where uploaded images are stored

---

# Accounts

Incoming maintainer has administrator access to:

□ GitHub

□ Shared committee email

□ Domain registrar

□ DNS provider

□ Password manager

□ Decap CMS

At least two committee members should always retain administrator access.

---

# Documentation

Incoming maintainer has read:

□ Project Overview

□ Setup Guide

□ Site Structure

□ Content Editing Guide

□ Technical Maintenance Guide

□ Deployment Guide

□ Accounts Guide

---

# Final Checks

The incoming maintainer can answer:

Where is the repository?

How is the website published?

How are pages edited?

How do I restore an older version?

Who owns the domain?

Where are passwords stored?
